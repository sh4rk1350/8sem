## 1. Диаграмма вариантов использования (Use Case Diagram)

![Use Case Diagram](./images/use-case-diagram.png)

**О чём:** Показывает основных акторов (Пользователь, Администратор) и их взаимодействие с системой. Описаны ключевые сценарии: анализ одного отзыва, пакетный анализ, выбор модели, просмотр истории и статистики, управление моделями (для администратора).

## 2. Диаграмма классов (Class Diagram)

![Class Diagram](./images/class-diagram.png)

**О чём:** Описывает статическую структуру системы. Основные классы: `SentimentAnalyzer` (анализ тональности), `VADERAnalyzer`, `TransformersAnalyzer` (конкретные стратегии), `WebController` (обработка запросов), `StatisticsManager` (статистика), `HistoryManager` (история). Показаны атрибуты, методы и связи (наследование, композиция, ассоциация).

---

## 3. Диаграмма последовательности (Sequence Diagram)

![Sequence Diagram](./images/sequence-diagram.png)

**О чём:** Показывает динамику обработки одного запроса на анализ тональности. Отображает взаимодействие между пользователем, веб-контроллером, анализатором и выбранной моделью (VADER или RuBERT), а также обновление статистики и истории.

## 4. Диаграмма компонентов (Component Diagram)

![Component Diagram](./images/component-diagram.png)

**О чём:** Показывает архитектуру системы на уровне компонентов: клиентская часть (браузер), веб-сервер (Flask), компонент анализа (модуль с моделями), база данных (опционально). Отображены интерфейсы (REST API, вызов моделей) и зависимости между компонентами.
